# MeetMatch AI — Frontend

React + Vite + TypeScript + Tailwind. Работа ведётся в ветке `frontend` существующего репозитория. Backend и Telegram-бот не входят в этот пакет.

## Запуск

Нужен Node.js 22.12+ (проверено на Node.js 24).

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev
```

PowerShell: вместо `cp` можно использовать `Copy-Item .env.example .env`. Адрес по умолчанию: `http://127.0.0.1:5173`. Без `.env` приложение сразу работает в демо-режиме. Для production: `npm run build`, затем `npm run preview`. На статическом хостинге направьте неизвестные пути на `index.html`, чтобы прямые переходы на маршруты SPA работали.

```bash
npm test
npm run build
```

Если системный npm cache недоступен, используйте `npm ci --cache <доступная-папка>`. ESLint не настроен; TypeScript strict проверяется сборкой, поведение — Vitest.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `VITE_SUPABASE_URL` | URL проекта Supabase |
| `VITE_SUPABASE_ANON_KEY` | Публичный anon-ключ проекта |
| `VITE_API_BASE_URL` | URL backend, например `http://localhost:8000` |
| `VITE_USE_MOCK_API` | `true` включает фиксированные демонстрационные ответы |

Переменные `VITE_*` публичны и попадают в клиентскую сборку. Приватные ключи сюда не помещать. `.env` и зависимости уже исключены корневым `.gitignore`.

Чтобы отключить mock:

```dotenv
VITE_API_BASE_URL=http://localhost:8000
VITE_USE_MOCK_API=false
```

После изменения переменных перезапустите Vite / пересоберите приложение. Пустой `VITE_API_BASE_URL` всегда включает mock, даже при `VITE_USE_MOCK_API=false`. Поэтому `.env.example` намеренно оставляет URL пустым для рабочего первого запуска. API-адрес задаётся явно для интеграции.

| Supabase | API | Режим |
| --- | --- | --- |
| Настроен | Настроен | Реальная авторизация и API |
| Настроен | Mock | Реальная авторизация, демонстрационные рекомендации |
| Нет | Настроен | Анкета без регистрации, реальный `/api/match` |
| Нет | Mock | Полностью демонстрационный режим |

Демо-режим отмечен баннером. Auth-страницы без Supabase предлагают перейти к анкете и не имитируют регистрацию или подтверждение email. Личный кабинет требует реальную подтверждённую сессию даже при mock API. API-ошибки не вызывают скрытого переключения на mock.

## Supabase

1. Включить Email provider и **Confirm email**.
2. Указать Site URL локального или production-приложения.
3. Добавить разрешённые Redirect URL: `http://localhost:5173/verify-email`, `http://127.0.0.1:5173/verify-email` и `https://YOUR_DOMAIN/verify-email`.
4. Заполнить два публичных значения Supabase в `.env`.

Email считается подтверждённым только при наличии `user.email_confirmed_at`. Подтверждение отслеживается через SDK `onAuthStateChange`. Повторная отправка имеет cooldown 60 секунд. Пароли живут только в форме и очищаются после запроса; приложение не пишет их в storage. Сессией управляет SDK Supabase; приложение не дублирует токены. При наличии сессии API получает `Authorization: Bearer …`. Ответы 401/403 очищают сессию и переводят на вход.

## Маршруты

| Путь | Доступ |
| --- | --- |
| `/` | Все |
| `/register`, `/login` | Гости; сессия перенаправляется в кабинет |
| `/verify-email` | Все |
| `/onboarding`, `/matches` | Подтверждённая сессия или демо-auth |
| `/profile/setup`, `/profile/edit`, `/dashboard` | Подтверждённая сессия |
| Остальные | 404 |

RU по умолчанию; RU / KZ / EN переключаются без перезагрузки. Выбор языка хранится в `localStorage('meetmatch.lang')`. Казахские переводы требуют редакторской проверки носителем языка. Контент рекомендаций не переводится: показывается ровно текст backend, поэтому фиксированные демо-профили остаются на русском.

## API contract

Все контрактные типы находятся в `src/types/index.ts`; адаптация HTTP — в `src/services/api.ts`.

- **Зафиксировано**: `POST /api/match` получает ровно `{ role, stack, experience, interests, about, goal }`. Шесть значений goal сохранены из спецификации. Клиент не рассчитывает совместимость и не меняет порядок ответа; показывает первые пять валидных элементов. `score` должен быть конечным числом 0–100. Структурно неверный ответ и непустой массив без валидных элементов дают ошибку; отдельные неверные элементы отбрасываются с безопасным предупреждением.
- `processing_ms` указан обязательным в исходном контракте, но UI допускает его отсутствие согласно §4.7: тогда время скрыто. Mock не придумывает это значение. Внутренний `MatchResult` описывает такую терпимость, исходный `MatchResponse` сохранён.
- **Предположение**: `POST /api/feedback` принимает `{ match_id, action: "met" | "not_fit" }`, возвращает `{ ok: true }`. Отмена оценки не предусмотрена. Неуспешный ответ разрешает повторить действие.
- **Предположение**: `GET /api/profile/me` возвращает `{ email?, personal?, professional?, stats? }`; `PUT` принимает частичный `ProfileMe`, например `{ personal: { full_name, age, gender, city, phone } }`. 404 при первичном чтении трактуется как ещё не созданный профиль. Другие ошибки отображаются с повтором.
- **Предположение**: `POST /api/telegram/link` возвращает `{ code, deep_link?, expires_in? }`. UI использует только `https://t.me/<bot>?start=<code>` ссылки и не добавляет в них данные сессии. 404/501/сетевая ошибка дают «Скоро». Health endpoint пока не нужен для потока: кнопка активна только при реальном API, в mock сразу «Скоро».
- **Предположение**: `GET /api/health` возвращает `{ status: string }`.
- Требуется подтвердить проверку Supabase JWT на backend.
- Требуется настроить CORS для `http://localhost:5173`, `http://127.0.0.1:5173` и production-домена, включая заголовок `Authorization`.
- Требуется подтвердить, сохраняет ли `PUT /api/profile/me` профессиональную анкету. Пока она хранится в `sessionStorage('meetmatch.onboarding.draft')` и отправляется в `/api/match`; кабинет может восстановить её из `professional`, если backend его вернул. Смена цели сохраняет черновик и запускает новый подбор.

Timeout: 10 seconds for matching, 15 seconds for other requests. Backend errors use the common `{ error: { code, message, details } }` envelope; raw exceptions and stack traces are not shown to users.

## Хранение и демо-данные

Черновик содержит только профессиональную анкету и сохраняется между шагами и перезагрузками вкладки. Успешный подбор не удаляет его; выход из аккаунта удаляет черновик, рекомендации и mock-профиль. ФИО и телефон не пишутся приложением в браузерное постоянное хранилище. Mock-профиль и feedback живут только в памяти и исчезают при перезагрузке.

Демо-рекомендации — неизменный набор из пяти вымышленных профилей, независимо от ввода. Они не сортируются и не выдаются за AI-анализ. Главная явно помечает показатели как цели проекта. Никакой статистики реальных знакомств не выдумывается.

## Реализация и ограничения

- P0: главная, четыре шага анкеты, шесть целей, теги, валидация, draft, API-клиент, топ-5, loading/error/empty/partial/success, полный reason, копирование, адаптив, demo/mock.
- P1: регистрация/вход/выход, email verification/resend, личный профиль, кабинет с шестью разделами, редактирование, три языка, feedback.
- P2: умеренные анимации и reduced-motion, Telegram-код/таймер/«Скоро», смена пароля, предупреждение о несохранённых личных данных при закрытии/перезагрузке страницы.
- Предупреждение при внутренней SPA-навигации не реализовано. Блок статистики знакомств скрыт; семантика будущих `stats` ещё не согласована.
- Действующие Supabase и backend не предоставлены: реальное письмо, регистрация, JWT/CORS, сохранение профиля и Telegram требуют интеграционного прогона после настройки. Демо не считается проверкой реальной авторизации.

Исходная спецификация сохранена без смысловых изменений в `FRONTEND_SPEC.md`. Результаты проверки перечислены в `VERIFICATION.md`.
